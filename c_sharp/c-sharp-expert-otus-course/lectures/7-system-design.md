## 1.7. 28.05.2026 Архитектура высоконагруженных систем: System Design на примере In-Memory кэша

System Design: определение требований, разбиение на компоненты, выбор технологий, проектирование интерфейсов и протоколов, анализ производительности и масштабируемости, обеспечение надежности и безопасности

Требования функциональные (ФТ, что система делает), нефункциональные (НФТ, как система это делает)

НФТ: High Availability (высокая доступность), Scalability (масштабируемость), Performance (производительность), Durability (долговечность), Consistency (консистентность), Maintainability (поддерживаемость), Security (безопасность), Cost (цена)

ACID - это набор требований к транзакционной системе в реляционных базах данных

- Атомарность (atomicity) - транзакция выполняется как единое целое, либо все операции выполнены, либо ни одна не выполнена

- Согласованность (consistency) - после завершения транзакции система переходит из одного согласованного состояния всех данных в другое

- Изолированность (isolation) - параллельные транзакции не влияют друг на друга

- Долговечность (durability) - после завершения транзакции все данные фиксируются и сохраняются даже в случае сбоя

Виды кэша: in-memory (ОЗУ), распределенный (Redis), client-side (браузер или мобильное приложение), CDN (группа распределенных серверов)

P99 латентность — это метрика, которая отражает 99-й перцентиль времени отклика системы. Она показывает, за какое время обрабатываются 99% запросов, то есть только 1% запросов обрабатываются дольше этого значения

REST (Representational State Transfer) — архитектурный стиль взаимодействия между клиентом и сервером

Принципы REST: Клиент-серверная архитектура, Отсутствие состояния (Stateless), Кэширование, Единый интерфейс, Система слоёв (Layered System), Код по требованию (Code on Demand)
